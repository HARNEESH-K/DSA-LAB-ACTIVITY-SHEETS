Data Structure Trade-Offs

Interactive "Why DLL?" Comparison

Evaluating Doubly Linked List against alternative candidates.

CHOSEN SOLUTION

Doubly Linked List

Bidirectional Pointers (\(prev, next\))
Back Traversal:\(O(1)\)
Forward Traversal:\(O(1)\)
Visit (Append):\(O(1)\)
Branch Pruning:\(O(1)\) Amort.
Space Complexity:\(O(N)\)

Advantages: Instant bidirectional navigation. Forward branches can be detached in \(O(1)\) time without element shifting.

Dynamic Array / Vector

Contiguous Buffer
Back Traversal:\(O(1)\)
Forward Traversal:\(O(1)\)
Visit (Append):\(O(1)\)
Branch Pruning:\(O(N)\) Copy/Shift
Space:\(O(N)\) Over-alloc

Limitations: Truncating forward history requires copying or resizing the buffer in \(O(N)\) time.

Two-Stack Model

Back + Forward Stacks
Back Traversal:\(O(1)\) Push/Pop
Forward Traversal:\(O(1)\) Push/Pop
Visit (Append):\(O(1)\)
Full Traversal:\(O(N)\) Destructive
Space:\(O(N)\)

Limitations: Cannot inspect or search the history list in order without popping both stacks.

Single Stack

LIFO Stack
Back Traversal:\(O(1)\) Pop
Forward Traversal:Impossible
Visit:\(O(1)\)
Bidirectional:Unsupported
Space:\(O(N)\)

Limitations: Once a webpage is popped to go back, it cannot be recovered for forward traversal.

// browser_history.c - Phase 2 & 3 Review
void visit(BrowserHistory *h, char *url) {
    Node *f = h->current->next;
    while (f) { // Clear forward nodes
        Node *t = f->next; free(f); f = t;
    }
    Node *n = new_node(url);
    n->prev = h->current;
    h->current->next = n;
    h->current = n;
    h->pos++; h->length = h->pos + 1;
}

char* back(BrowserHistory *h) {
    if (!h->current->prev) return NULL;
    h->current = h->current->prev;
    h->pos--;
    return h->current->url;
}

Browser History Management Using Data Structures

💡 Why use a Doubly Linked List instead of an Array?
An Array requires contiguous memory. When visiting a new page after moving backward, deleting orphaned forward elements requires \(O(N)\) shifting or resizing. A Doubly Linked List detaches forward nodes via pointers in \(O(1)\) amortized time with zero shifting.
💡 How does visit() avoid memory leaks in C?
In C, orphaned heap blocks remain allocated until explicitly freed. Our visit() function traverses orphaned nodes starting at current->next with while (f) { Node *t = f->next; free(f); f = t; }, freeing all dropped nodes.
💡 Why not use a Circular Doubly Linked List?
A web browser history is strictly linear with a clear start and end. Making it circular would cause clicking Back at the homepage to wrap around to the newest page, violating standard navigation rules.
💡 What is the time complexity of Back and Forward?
Strictly \(O(1)\) constant time because pointers provide direct address access (current = current->prev or current = current->next).
